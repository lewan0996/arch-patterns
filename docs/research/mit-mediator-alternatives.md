# MIT alternatives to MediatR-style dispatch

Research checked 2026-11-15 for [Investigate a minimal dispatcher, MediatR fork or Wolverine](https://github.com/lewan0996/arch-patterns/issues/37). This note compares documented APIs and public repository metadata, not runtime compatibility or an owner selection.

## Closest API candidates

### martinothamar/Mediator

**MIT**, inspected main commit `8b87a0ed74747b7e4be907db220b930a50fbeb98`; latest GitHub release **v3.0.2**, published **2026-03-22**, with main last pushed September 1. Its documented request/command/query interfaces, notification handlers and `IPipelineBehavior` closely resemble MediatR's model. Important differences are source-generated dispatch, `ValueTask` APIs, generator setup in the executable host, and a **Singleton** default lifetime that should be changed deliberately to **Scoped** for scoped persistence/caller services. This is API resemblance rather than source/binary drop-in compatibility. [Pinned README](https://github.com/martinothamar/Mediator/blob/8b87a0ed74747b7e4be907db220b930a50fbeb98/README.md), [license](https://github.com/martinothamar/Mediator/blob/8b87a0ed74747b7e4be907db220b930a50fbeb98/LICENSE), [release](https://github.com/martinothamar/Mediator/releases/tag/v3.0.2).

The owner previously rejected this option over contributor concentration. Current public contributor metadata remains concentrated in the lead author; release activity does not resolve that concern or establish long-term support. Include it as a close technical alternative without silently reversing that preference. [Owner's earlier decision](https://github.com/lewan0996/arch-patterns/issues/35#issuecomment-6242121275), [contributors](https://github.com/martinothamar/Mediator/graphs/contributors).

### FreeMediator

**MIT**, inspected main commit `3b6026eb922ec6f35e4067f8be9b4300c4ebed4d`. It is a new implementation aiming for MediatR syntax compatibility, rather than a fork. Its `Task`-style sender/mediator, request handlers, notifications and open/closed pipeline behaviors make it the closest API-style match in this shortlist. It documents limitations including missing streaming support and a same-return-type limitation when multiple request handlers share one class. Notification pipelines are also supported. [Pinned README](https://github.com/steffenskov/FreeMediator/blob/3b6026eb922ec6f35e4067f8be9b4300c4ebed4d/README.md), [license](https://github.com/steffenskov/FreeMediator/blob/3b6026eb922ec6f35e4067f8be9b4300c4ebed4d/LICENSE).

Its changelog records **1.4.2** on **2026-09-17**, main was pushed November 9, and no GitHub Releases were listed at the time of research. Contributor metadata lists one human and two bots. Interpretation: useful for API familiarity, but a weaker candidate if contributor concentration remains a decisive selection criterion. Changelog/source activity is not a compatibility or maintenance guarantee. [Changelog](https://github.com/steffenskov/FreeMediator/blob/3b6026eb922ec6f35e4067f8be9b4300c4ebed4d/CHANGELOG.md), [contributors](https://github.com/steffenskov/FreeMediator/graphs/contributors).

## Immediate.Handlers

**MIT**, with latest GitHub release **v4.3.0**, published **2026-11-10**; inspected main/release-tip source `c4b47bbdbe4df6f81d7c9de9295d1b20a8582618`. It generates typed handlers and pipeline calls at compile time, using `[Handler]`, `HandleAsync` and `Behavior<TRequest,TResponse>`. Consumers inject the generated handler or `IHandler<TRequest,TResponse>` rather than calling an all-purpose MediatR-compatible sender. Streaming is documented. No MediatR-style notification fan-out surface was found in its README or source-path inventory; do not advertise full feature parity. [Pinned README](https://github.com/ImmediatePlatform/Immediate.Handlers/blob/c4b47bbdbe4df6f81d7c9de9295d1b20a8582618/readme.md), [license](https://github.com/ImmediatePlatform/Immediate.Handlers/blob/c4b47bbdbe4df6f81d7c9de9295d1b20a8582618/license.txt), [release](https://github.com/ImmediatePlatform/Immediate.Handlers/releases/tag/v4.3.0).

Generated `AddXxxHandlers` registration is per assembly and defaults to **Scoped** lifetime. Host composition can call each module's generated registration. An individual handler's behavior attribute overrides assembly-wide behavior selection, which matters for mandatory authorization. The public contributor metadata is concentrated in one human maintainer; current release activity does not resolve the owner's earlier contributor-concentration concern. [Registration template](https://github.com/ImmediatePlatform/Immediate.Handlers/blob/c4b47bbdbe4df6f81d7c9de9295d1b20a8582618/src/Immediate.Handlers.Generators/Templates/ServiceCollectionExtensions.sbntxt), [contributors](https://github.com/ImmediatePlatform/Immediate.Handlers/graphs/contributors).

Interpretation: a credible MIT typed-handler/pipeline alternative, with a different invocation style and less documented notification functionality than MediatR. It does not provide Wolverine's durable message recovery machinery.

## Paramore Brighter and Darker

**MIT**. Brighter's latest GitHub release is **10.8.1**, published **2026-10-22**, pinned commit `708fa74bf7d578a53c7093ed0879faaedfbf4357`. Its documented model uses `Command`/`Event`, `RequestHandler<T>` or asynchronous handlers and ordered middleware. `Send` invokes one in-process handler, `Publish` invokes multiple in-process event handlers, and `Post` sends through an external broker. It also has a transactional outbox and the retained RabbitMQ/Azure Service Bus transport families. Darker is its separately packaged query-side counterpart. These are documented capabilities, not proof of the catalog's provider/transport matrix. [Pinned README](https://github.com/BrighterCommand/Brighter/blob/708fa74bf7d578a53c7093ed0879faaedfbf4357/README.md), [license](https://github.com/BrighterCommand/Brighter/blob/708fa74bf7d578a53c7093ed0879faaedfbf4357/LICENCE.txt), [release](https://github.com/BrighterCommand/Brighter/releases/tag/10.8.1), [Darker](https://github.com/BrighterCommand/Darker).

Brighter has a longer public development history and several substantial human contributors, while remaining lead-maintainer dominated. This is a stronger breadth signal than a one-author new replacement, not a support guarantee. Brighter's documented resilience integration uses Polly; exact transitive versions and any direct application references need the catalog's existing dependency/fee review. Darker's latest GitHub release is **4.1.1** (2025-06-02), while its main branch remains active in November 2026. Do not assume a feature described on main exists in the last release. [Brighter contributors](https://github.com/BrighterCommand/Brighter/graphs/contributors), [Darker releases](https://github.com/BrighterCommand/Darker/releases).

Current Darker documentation explicitly warns that processor scopes may not reuse the request's scoped EF services, and documents opt-in request-scope integration. This is an integration point to verify at the chosen versions, not automatic multi-context atomicity. Interpretation: Brighter/Darker is the stronger integrated framework alternative to examine if handler pipelines plus durable messaging are both required, but its APIs and two-processor CQRS model are not a MediatR drop-in. [Darker scope guidance](https://github.com/BrighterCommand/Darker#usage-with-microsoftextensionsdependencyinjection).

## Nearby projects and exclusion

**Foundatio.Mediator is Apache-2.0, not MIT**, at inspected main commit `24ff5237224fd147f8761facda20abe437f85458`. It provides convention-based plain handlers, `Invoke`, source generation/interceptors and Before/After/Finally/Execute middleware. That is closer to Wolverine's conventions than MediatR interface compatibility. Its latest GitHub release is v1.3.3 (2026-07-07); main was active on 2026-11-12. Exclude it from a strict-MIT shortlist. [License](https://github.com/FoundatioFx/Foundatio.Mediator/blob/24ff5237224fd147f8761facda20abe437f85458/LICENSE.txt), [README](https://github.com/FoundatioFx/Foundatio.Mediator/blob/24ff5237224fd147f8761facda20abe437f85458/README.md), [release](https://github.com/FoundatioFx/Foundatio.Mediator/releases/tag/v1.3.3).

**LiteBus is MIT**, and its current documentation includes commands, queries, events and optional durable messaging. It should not be described as necessarily in-process-only. Its distinct mediators and extensive optional package graph make it a broader, less API-compatible option; no focused fit assessment was completed here. [Official repository and documentation](https://github.com/litenova/LiteBus).

## Selection boundary

MediatR-style synchronous dispatch can help implement before-commit event handling, but changing the dispatcher does not by itself join separate EF contexts into one transaction. A lightweight mediator also does not replace Wolverine's outbox, broker integration and dead-letter replay facilities; those need a separate messaging component. Brighter is a broader candidate that includes those classes of capability and therefore needs a separate fit check before claiming equivalence.
